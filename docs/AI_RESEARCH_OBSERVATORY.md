# AI Research Observatory

The native Hodgepodge page is `content/hodgepodge/ai-research-observatory.md` with a Hugo layout in `layouts/hodgepodge/ai-research-observatory.html`. The browser loads `static/data/ai-research-observatory.json`; no server or public write API is needed on GitHub Pages. UI behavior is split between `static/js/ai-research-observatory-core.js` (pure calculations) and `static/js/ai-research-observatory.js` (rendering), with site-aware styling in `static/css/ai-research-observatory.css`.

The pinned companion post is `content/posts/ai-research-tracker.md`. Its 26-conference, five-field organizer submission/acceptance figures and award highlights are curated in `data/ai_research_observatory/tracker_history.json` and expanded into `static/data/ai-research-conference-history.json`. A separate per-venue chart reads verified main-track totals, bibliography fallback counts, and observed AI matches from the observatory snapshot. None of those counts are organizer acceptances. The Observatory retains its broader 88-series catalog.

## Data flow

1. Edit `scripts/ai_research_venues.py` and regenerate `data/ai_research_observatory/venues.json` with `python3 scripts/ai_research_venues.py`. The legacy 53-series inventory is the union of AI-facing CORE 2023 A*/A (FoR 4602/4603/4611), CCF 2026 AI A/B, and TH-CPL 2019 AI A, plus ranked AI-facing retrieval, recommender, multimedia, speech, and data-mining series from other ranking categories. The expanded catalog also has the 23 requested cross-area series and 12 evidence-backed additions; see the [ranked-venue audit](AI_RESEARCH_OBSERVATORY_VENUE_AUDIT.md) for inclusion and exclusion decisions. The public snapshot now contains all 88 series, but a calendar cell is not necessarily verified coverage. Ranked memberships remain separate fields, and a missing OpenAlex source ID is not imputed. `ai_native: false` identifies cross-area venues for AI-topic review.
2. Run the dependency-free collector. For the 35 new cross-area series, `data/ai_research_observatory/cross_area_sources.json` provides per-edition source rules. `scripts/ai_research_bibliography.py` scans eligible main-track bibliography titles before `scripts/ai_research_relevance.py` classifies AI candidates; the public paper cap applies only after classification. An official complete track index may yield `main_track_total`; a DBLP stream can yield `bibliography_total` but is not promoted to main-track without verification. `ai_matched_count` is an observed subset of `scanned_count` eligible records, with unresolved decisions and scan status recorded separately. For the earlier AI-facing inventory, OpenAlex samples works by verified source ID (default 25, maximum 100), accepting `article` and `conference-paper` types while excluding obvious non-paper titles. OpenAlex's [`conference-paper` classification](https://help.openalex.org/data/work-types/) is still rolling out, so filtering to that type alone produces false zero years. Independent NeurIPS main-track, PMLR ICML/AISTATS/COLT/UAI, ACL Anthology ACL/EMNLP/NAACL/EACL/COLING main-volume, and CVF CVPR/ICCV/WACV indexes contribute at most 250 records per venue-year. Legacy `source_total` means OpenAlex source matches, not a proceedings census. OpenAlex responses are cached for six hours and official HTML for one day in `.cache/ai-research-observatory/`.
3. Paper records merge by normalized venue/year/title, retaining both source links. OpenAlex supplies paper-specific affiliations and citation percentiles where available; official-only papers keep those fields unknown. A successfully queried source replaces its sample. Failed sources retain previously verified papers and are flagged in coverage. `data/ai_research_observatory/featured_proceedings.json` forces verified official papers into a capped sample.
4. PMLR `Software` links establish paper-specific code evidence. The collector recognizes GitHub repository links and queries the GitHub API for stars, latest push, archive/fork state, and a checked-at timestamp within a request cap. GitHub stars and pushes do not prove business use or future maintenance. A failed repository check clears live stars and activity to unknown without deleting the paper or its reviewed association.
5. Evidence-backed entries in `data/ai_research_observatory/reviews.json` override metadata on every refresh. An `"exclude": true` review with a reason and HTTPS evidence suppresses an incorrect record. To add an OpenAlex paper missed by the cap, use `data/ai_research_observatory/manual_works.json` with its work ID, venue, year and official evidence; the collector verifies its source/year/type. For an official-only paper, use `featured_proceedings.json` and key its review by the official URL. The generated JSON is committed as the public snapshot; the browser makes no live metadata requests.
6. `.github/workflows/refresh-ai-research-observatory.yml` runs weekly for the current and previous calendar years. Set a verified `OPENALEX_API_KEY` repository Actions secret for OpenAlex metadata refresh; without it, the weekly job refreshes only official proceedings and GitHub evidence because anonymous daily usage cannot reliably cover the catalog. In Actions, **Refresh AI Research Observatory** → **Run workflow** offers `refresh_scope: backfill-2020` to process 2020 through the current year; this mode requires the secret and does not fall back to a keyless run. `GITHUB_TOKEN` is supplied by Actions. NeurIPS index mappings stop at 2025 until the 2026 main-track volume is verified; ICML 2026 uses PMLR volume 306. The workflow tests, builds, checks links, and commits only the snapshot.

For a local, keyless bibliography audit, seed a temporary output from the current snapshot so prior OpenAlex papers survive:

```sh
tmpdir=$(mktemp -d)
cp static/data/ai-research-observatory.json "$tmpdir/snapshot.json"
env -u OPENALEX_API_KEY python3 scripts/refresh_ai_research_observatory.py \
  --from-year 2020 --to-year 2026 --skip-openalex --github-cap 0 \
  --output "$tmpdir/snapshot.json" --cache-dir "$tmpdir/cache"
python3 -m unittest discover -s scripts -p 'test_ai_research*.py'
node scripts/test_ai_research_observatory_core.cjs
node scripts/test_ai_research_tracker.cjs
./scripts/check_posts_have_tags.sh
hugo --minify --cleanDestinationDir
./scripts/check_internal_links.sh public
```

The full OpenAlex enrichment pass remains an Actions-only `backfill-2020` run with its configured repository secret; a local `--skip-openalex` run does not verify that pass. Use `--venues osdi icse` for a scoped refresh or `--cached-only` for an OpenAlex-cached partial rebuild. Inspect every catalog venue-year cell before claiming full coverage; biennial conferences also have non-meeting years. HTTP 429 stops further OpenAlex calls in that run; missing results remain marked rather than set to zero. Published paper records remain **capped samples**, not a complete paper census. Cross-area venues have no verified OpenAlex source ID, and most have no independently reconciled official main-track index yet. OpenAlex [authentication and limits](https://help.openalex.org/api/authentication/) and GitHub [rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) may change.

### Local backfill audit, 2026-10-16

The keyless snapshot has 616 explicit cells (88 series x seven years) and 22,803 paper records, retaining all 20,706 prior native records. Its 35 cross-area series have 216 `partial` bibliography cells, 20 `unresolved` gaps, two `not-held` years, six `not-yet-published` years, and only one `verified` main-track cell: OSDI 2025, where the [USENIX technical sessions](https://www.usenix.org/conference/osdi25/technical-sessions) reconcile with 53 DBLP records. The 18,564 cross-area bibliography records yielded 2,470 observed AI matches and 2,097 published AI samples; these are not organizer acceptance counts or interchangeable denominators. SoCC 2020-2025 stays unresolved until a paper-level full-research track index separates its [research, industry, short, and vision categories](https://acmsocc.org/2026/papers); 2026 is not yet published. Exact DBLP book labels exclude ICSE side tracks, pre-2024 FSE workshops, SC workshop volumes, and Middleware extended abstracts. The 2026 SoCC conference is scheduled for November, and the shared DBLP `conf/cloud` stream returned IEEE CLOUD records rather than SoCC publications, so no SoCC 2026 papers are published here.

The 53 legacy series retain 177 `no-index-records` cells with `source_total: 0`, 147 `sample` cells, 35 `unmapped` cells, and 12 `source-scan` cells. A zero OpenAlex source match, including ECCV 2020 and CIKM 2020, is an **index gap**, not zero venue publications. Such cells do not produce a venue-count chart point; publisher-index entries, when present, stay separately labelled. The secret-backed OpenAlex pass, broader official-index reconciliation, and live-site confirmation are still pending outside this local audit.

For a scoped validation backfill, use `--venues osdi --from-year 2025 --to-year 2025 --output /tmp/ai-observatory-check.json --cache-dir /tmp/ai-observatory-cache`; these paths leave the committed snapshot and cache untouched. Cross-area collection scans every eligible bibliography title before any public paper cap, and cached OpenAlex DOI lookups run in bounded batches when enabled. Coverage separates verified `main_track_total`, indexed `bibliography_total`, observed `ai_matched_count`, unresolved AI decisions, and `sampled_papers`. A missing count is `null`, not zero. The production AI scan considers explicit title evidence, durable reviewed include/exclude decisions, and exact structured primary topics when metadata is available. **Abstract-only AI matches require manual review** with an HTTPS bibliography DOI or paper URL and evidence; free-text abstracts do not confirm published cross-area AI matches because related-work sentences can produce false positives.

## Reviewed corrections

GitHub Pages is static. To correct a classification or attach award/code/leadership evidence, edit `data/ai_research_observatory/reviews.json` and regenerate the snapshot. Use the OpenAlex ID, DOI, or official proceedings URL as the key. Every correction **requires an HTTPS evidence URL**. Example:

```json
{
  "https://openalex.org/W123": {
    "leadership": "Joint",
    "award": true,
    "repository_url": "https://github.com/org/repo",
    "repository_evidence_url": "https://example.org/paper-that-links-the-repository",
    "adoption_status": "integration",
    "adoption_evidence_url": "https://example.org/integrator-release-notes",
    "maintenance_status": "active",
    "maintenance_evidence_url": "https://github.com/org/repo/releases",
    "resources": "8 NVIDIA H100 GPUs; source states 320 GPU-hours",
    "compute": {"gpu_type": "NVIDIA H100", "gpu_count": 8, "gpu_hours": 320, "accelerator_type": null, "training_flops": null, "model_parameters": null, "training_cost": null},
    "funding": "Institutional grant acknowledged in paper",
    "review_note": "Leadership supported by author-contribution statement.",
    "reviewer": "Your name",
    "date": "2026-10-15",
    "evidence_url": "https://example.org/paper-or-official-award-page"
  }
}
```

Only use `award: false` or `code_available: false` after an actual review supporting the negative. A repository needs a paper-to-repository association URL; a matching name alone is insufficient. Adoption is `Unknown`, `integration`, `pilot`, or `production`: use `production` only for explicit deployment or case-study evidence, never stars or a library integration alone. Maintenance is `Unknown`, `active`, or `inactive`, with dated release/maintainer evidence and a `date` field; its score expires after 365 days unless re-reviewed. `active` is an assessment at review time, not a promise. Leadership needs explicit project-role evidence. Reviews are versioned in git. The current reviewed example is FlashAttention; its PyTorch integration does not prove business deployment.

## Updating the pinned research tracker

Edit `data/ai_research_observatory/tracker_history.json` for the five fields, 26 conferences, known organizer counts, not-held years, and awards. Each `known` entry needs a venue ID, year, exact track scope, and a direct organizer source; use `submitted_source` and `accepted_source` when the numbers come from different pages. Run `python3 scripts/build_ai_research_tracker_history.py` to rebuild the explicit 2020–2026 grid in `static/data/ai-research-conference-history.json`. Do not edit the generated file directly, infer submissions from a rounded acceptance rate, or turn missing figures into zero. Review current-cycle acceptances separately from prior-cycle revise-and-resubmit papers. Each award needs the organizer-confirmed paper title and award, venue, year, a short editorial field and topic list, and a source URL. The keyword cloud counts only those selected award labels. The industry/university title-keyword plot uses only the 26 Tracker venues, explicit regexes in `static/js/ai-research-tracker.js`, and classified first-author sectors from the merged AI-paper snapshot. Official-only papers without affiliations are excluded from those curves. Review both the keyword rule and source coverage before interpreting a change.

The Tracker and Observatory embed `data/ai_research_observatory/venues.json` at Hugo build time. The Tracker filters its controls and analyses to the 26 selected series; the Observatory exposes the full 88-series catalog. Venue, area, rank, and year controls navigate inventory and coverage. The Tracker main-track line plots only non-stale `status: verified` rows with a numeric `main_track_total`; bibliography-only rows appear as a separate fallback, while a numeric `ai_matched_count` appears as observed AI matches with its `scanned_count` denominator and source links. Two distinct legacy series show `source_total` as OpenAlex source matches and `official_total` as publisher index entries, including both when a year has both. Neither is a verified main-track or organizer acceptance count. A missing, unresolved, source-error, not-held, or not-yet-published cell is a gap, never an inferred zero. The Observatory coverage view also reports the track scope, source URLs, scan/partial/stale flags, unresolved AI decisions, and distinct sampled-paper count where published. Legacy `scanned` and `official_sampled` are OpenAlex and publisher sample sizes, respectively; neither is the cross-area AI scan denominator. The paper analyses use only the published AI paper ledger; standalone arXiv reports remain outside conference totals.

As of 2026-10-16, NeurIPS 2022 uses [9,634 full submissions](https://blog.neurips.cc/2022/08/01/updates-from-the-program-chairs/) and [2,672 main-track acceptances](https://blog.neurips.cc/2022/11/22/getting-ready-for-neurips-3-2022-conference-highlights/) from separate organizer reports, not the combined-track 2,905 acceptances in its fact sheet. [ICML 2025](https://media.icml.cc/Conferences/ICML2025/ICML2025_Fact_Sheet.pdf) has 3,260 main-track papers but no exact submission count in the cited sheet, so its submission cell stays `null`. OSDI acceptances use current-cycle decisions rather than proceedings totals that include prior-cycle revise-and-resubmit work; 2026 also adds an Operational Systems track, as its linked scope notes. Euro-Par's annual counts come from the publisher-hosted conference proceedings and cover the whole main conference, not only its compiler-related papers. Standalone ASPLOS 2024-2026 and EuroSys 2026 cycle figures are not added into an annual total because revision and carry-over rules could double-count papers. Separate HPCA/ISCA industry-track counts do not stand in for main-track figures. Other unverified venue-years remain unplotted until an organizer source and comparable scope can be confirmed.

When asked to refresh the tracker, audit existing records first, remove incorrect ones, add newly confirmed organizer figures and awards, update `reviewed_at` and the post's `lastmod`, and rebuild the history JSON. Regenerate the observatory snapshot only if its records or classifications changed. Run the tests/build/link checks above and commit the source and generated data. The weekly action refreshes sampled publication and GitHub metadata, not organizer counts, award curation, or production/maintenance reviews; those require manual review. GitHub Pages cannot perform an authoritative live conference-count refresh in the browser.

## Method and interpretation

- Venue inclusion uses the linked [CORE 2023 export](https://portal.core.edu.au/conf-ranks/?by=all&page=1&search=&sort=arank&source=CORE2023), [CCF 2026 recommended-list PDF](https://lib.ecnu.edu.cn/_upload/article/files/e2/d9/dd45764345088869915f6b3617a4/28891f1f-eb8a-4000-a279-6e7141d92488.pdf), and [TH-CPL PDF](https://numbda.cs.tsinghua.edu.cn/~yuwj/TH-CPL.pdf). Ranked memberships and editions are preserved independently. A*/A are mapped to prestige 1.0, B to 0.75. This is an editorial score proxy, not an official cross-system equivalence.
- AI-native venues accept their indexed conference-paper metadata. AI-adjacent multimedia, retrieval, recommender, and data-mining venues require the `AI_WORDS` match against title or OpenAlex topic/keyword metadata; each record stores the applied rule. This heuristic has unmeasured precision and recall. Cross-area AI matches require venue-wide eligible-title scanning and paper-level review; their manifest is not a paper-count source.
- First-author sector uses only the first byline author's paper affiliations. Both company and education yield `Mixed`. All author affiliations yield team sector `Joint` if company and education both occur. Team sector does **not** imply jointly led work. Unknown affiliations stay unknown. Corresponding and senior author names are recorded when OpenAlex exposes them; they do not determine leadership.
- A paper with multiple first-author affiliation countries contributes `1 / n` to each map count. The institution counter counts distinct displayed institution names, not consolidated legal entities.
- Score: `6 × sum(weight × available component value) / sum(available weights)`; evidence coverage is `sum(available weights) / sum(selected weights)`. Defaults are citation percentile 40, venue 15, award 10, public code 5, GitHub stars 5, recent repository activity 5, reviewed maintenance 10, and reviewed adoption 10. Stars use a capped log scale (`log(1+stars)/log(1001)`); activity is 1 for a push within 180 days and declines to 0 by 365 days. GitHub metrics are eligible only from an un-forked repository checked within 45 days. Reviewed maintenance is active 1 / inactive 0 with evidence no older than 365 days; reviewed adoption is pilot .35 / integration .6 / production 1. These ordinal mappings are **editorial proxies**, not calibrated outcome probabilities or measured business adoption. A score needs two components and 55% selected-weight coverage, or four including code and reviewed adoption or maintenance with 50% coverage. The weight panel shows an audit for the first filtered paper, then the last paper opened if it remains filtered; each paper dialog shows its own audit. Each selected component reports its weight, value, contribution, inclusion, or omission reason. Zero-valued reviewed evidence remains included; unknown evidence has no value or contribution and is omitted from the denominator. A stale GitHub check omits stars and activity; an expired maintenance review omits maintenance. When no weights are selected, the score is unavailable and coverage is undefined (reported as 0 by the API). Differently evidenced records are not directly comparable, and scored impact share is not a population estimate.
- Trend counts are tracked sample counts. Percentages use classified first-author records in the filtered sample; impact contribution uses scored values in that same classified set. Filters affect charts, map, metrics, and table. The table and exports include the filtered set and currently selected weights.
- GPT-3, ChatGPT, LLaMA/GPT-4, Llama 3, DeepSeek-R1/GPT-5 are contextual releases linked to their originators. No causal effect is inferred. There is no verified GPT-6 milestone in this dataset; 2026 is labelled a research watch, not a release assertion.

## Limits before any research conclusion

This is **not a census**. The rank catalog is broader than the published coverage: OpenAlex source IDs miss papers and entire years, and some venues lack a verified source mapping. Independent NeurIPS/PMLR/ACL/CVF proceedings indexes fill some gaps, but their 250-record paper sample cap remains a sample; the parsed index total is only a source-page count. Cross-area DBLP bibliography totals are not automatically complete main-track totals; only verified track-specific indexes receive that label. Merging by normalized title can miss differing titles or rarely combine collisions. Main-track and index totals are not interchangeable with organizer acceptance totals. Missing affiliation/citation data on official-only records makes sector and impact comparisons selective. OpenAlex can mislabel paper types or include workshops. DOI-level reconciliation against official proceedings and [DBLP](https://dblp.org/) remains necessary before conference-wide estimates. Recent-year counts and citations have lag.

Landmark corporate technical reports outside peer-reviewed proceedings are excluded, so this page cannot answer whether industry dominates **all** AI research. GitHub stars may be unrelated to adoption; a recent push can be automation; a public repository does not prove deployed business use. Adoption and maintenance reviews are sparse and time-sensitive. The dashboard reports missingness instead of guessing. Revisit track identity, DOI/title reconciliation, institution parentage, code association, industry-use claims, and audited keyword precision before publication-grade inference.
